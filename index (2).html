Skip link (SC 2.4.1)

The "Skip to main content" link at the very top of this page is the first tab stop. It is hidden until it receives focus, then lets keyboard users bypass the header and navigation.

What to test

  • Activate the button, then press Tab: the skip link appears.
  • Press Enter on it: focus moves to the main region.

ARIA used

  • None. A native link to #main plus tabindex="-1" on the target.

Tabs

Only the active tab is in the Tab order. The tablist is one stop, then arrow keys move within it.

← → move and activate, Home first tab, End last tab.

Roving tabindex keeps long widgets from forcing users to press Tab dozens of times.

What to test

  • Tab into the tab row, use arrows, Home and End. Tab again: you land in the panel.
  • Screen reader: hear "tab, 2 of 3, selected".

ARIA used

  • role=tablist / tab / tabpanel
  • aria-selected, aria-controls, aria-labelledby, roving tabindex

Accordion

A region such as header, nav, main or footer that lets screen reader users jump around.

The text a screen reader announces for a control, from its label, aria-label, content or alt.

Only when native HTML cannot express the role or state. No ARIA is better than bad ARIA.

What to test

  • Tab to a header, press Enter or Space. Screen reader: "expanded" / "collapsed".

ARIA used

  • aria-expanded, aria-controls on the button; role=region + aria-labelledby on panels

Modal dialog

What to test

  • Focus moves into the dialog. Tab and Shift+Tab cycle inside it only.
  • Esc closes it and focus returns to this button.

ARIA used

  • role=dialog, aria-modal=true, aria-labelledby, aria-describedby
  • The page behind is made inert. (A native <dialog> with showModal() is the simpler modern alternative.)

Dropdown menu (menu button)

What to test

  • Enter, Space or ↓ opens (↑ opens on last item). Arrows wrap, Home/End jump, Esc closes and returns focus.

ARIA used

  • aria-haspopup=menu, aria-expanded, role=menu / menuitem / none

    Toast / status message (SC 4.1.3)

    Messages appear in the bottom-right corner and stay until dismissed (no time limit, SC 2.2.1).

    What to test

    • Screen reader announces the message without moving focus.

    ARIA used

    • role=status (implicit aria-live=polite). Use role=alert only for urgent errors.

    Module 4: Audit report & checklist

    Be honest about automation

    Automated tools (axe DevTools, Lighthouse, WAVE) detect only a portion of WCAG problems. Commonly cited estimates range from roughly 30% to 57%, depending on how issues are counted. They cannot judge whether alt text is meaningful, whether focus order makes sense, or whether an interaction is usable. Manual testing with a keyboard and a screen reader is required.

    WCAG 2.1 Level A and AA checklist

    Mark each criterion Pass, Fail or Not applicable. Anything left unmarked counts as "Not tested". Criteria are grouped by the four POUR principles.

    Test-method guide

    Keyboard-only testing

    1. Unplug or ignore the mouse.
    2. Press Tab from the top: is there a skip link? Is every control reachable, in a logical order?
    3. Can you always see where focus is?
    4. Operate every control with Enter, Space and arrow keys. Can you leave every widget (Esc, Tab)?

    Screen reader testing

    • NVDA with Firefox or Chrome (Windows, free).
    • JAWS with Chrome (Windows, commercial).
    • VoiceOver with Safari (macOS: Cmd+F5; iOS: Settings, Accessibility).
    • TalkBack with Chrome (Android).

    Check: landmarks and headings lists, form labels, button names, live-region announcements, table navigation.

    Zoom and magnification

    • Browser zoom to 200% (SC 1.4.4) and 400% (SC 1.4.10): no clipped text, no horizontal scrolling, nothing lost.
    • Test the OS magnifier (Windows Magnifier, macOS Zoom).
    • Apply a text-spacing bookmarklet or extension for SC 1.4.12.

    Contrast tools

    • Browser DevTools colour picker shows the ratio.
    • TPGi Colour Contrast Analyser (desktop eyedropper).
    • WebAIM Contrast Checker (web).
    • Check text (4.5:1 / 3:1 large) and UI components and graphics (3:1) in every theme and state.

    Automated tools

    • axe DevTools, Lighthouse (uses the axe engine), WAVE.
    • Run them early and in CI to catch the easy 30-57%, then do the manual passes above.
